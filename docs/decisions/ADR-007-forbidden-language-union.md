# ADR-007 — 禁用输出语言按并集强制执行

状态：Accepted（V0.1）
日期：2026-10-07

## 背景

冻结的 `role-model-v1.0.json` 里 `forbiddenLanguage` 只有 5 条：`就是这种人`、`政治可靠`、`忠诚`、`应当吸纳`、`应当淘汰`。

而《工程圣经》§24 明确禁止的还有：`值得信任`、`不值得信任`、`危险人物`；§18 禁止 `撒谎概率`、`欺骗指数`、`真实性评分`。

冻结内容文件与代码约束之间存在缺口。仅靠冻结列表，机器无法拦住 §24 点名禁止的输出。

## 决策

代码侧维护 `REQUIRED_FORBIDDEN_LANGUAGE`（`src/domain/validation.ts`），并在 `computeRoleFits` 中与冻结列表取**并集**后强制屏蔽（`src/engine/role-fit.ts`）。命中即替换为 `[已按产品边界屏蔽]`。

同时 `validate:questions` 的 `forbidden_language_list_gap` 检查会把"冻结文件缺了哪几条"作为警告持续报出来，而不是让缺口沉默。

## 后果

- 即使内容文件未补齐，机器也无法输出信任类/危险类标签。
- 缺口仍然可见：校验报告每次都列出缺失项，直到内容文件补齐。
- 不修改冻结的题库内容文件。内容变更应由题库作者决定并单独版本化，不在工程改动中顺手改内容。
- 代价：并集列表在代码里，fork 后若使用另一套语言（非中文），需要替换该列表。
