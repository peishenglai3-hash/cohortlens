# ADR-009 — 演示数据是模拟的，且必须自述为模拟

状态：Accepted（V0.1）
日期：2026-10-07

## 背景

圣经 §65 原本要求在正式题库完成前先做 10–15 道中性 Demo Fixture 来验证链路。现在正式题库已经存在，于是出现一个新的风险：为了让演示"好看"，很容易伪造一份看起来很真实的作答，或者干脆每次只选最高分选项。

## 决策

1. 演示跑在**正式 120 题题库**上，不使用精简 fixture 作为主链路证明。
2. 作答由引擎自带的 PRNG 从同一 seed 派生（`simulateAnswers`），因此演示**逐字节可复现**，不是随机噪声。
3. 演示作答**故意不总是选最高分项**：`balanced` 模式下约五成选最高、三成选最低、两成随机。理由是一个只会"答满分"的演示恰好会隐藏本切片最需要暴露的问题（维度分数粒度过粗、B/C 层只有 1-2 题）。
4. 输出中明确标注"模拟作答方式（由种子驱动，不是真人数据）"，导出的 JSON 里也带 `note` 字段自述。
5. 小型手写 fixture（`tests/fixtures/packs.ts`）只用于单元测试的边界分支：题库本身没有反向题、没有同族题、只有一档难度，这些分支必须用手写数据才能覆盖。fixture 不进入构建产物。

## 后果

- 演示结果不是"某人的画像"，而是"引擎在给定输入下的输出"。
- 演示同时充当 §50 确定性测试：同一 seed 两次运行必须逐字节相同，否则脚本以非零码退出。
- 代价：演示结果看起来不会"漂亮"——会出现 0 分维度、33 分维度、置信度 50% 的维度。这是如实反映，不是缺陷。
