# ADR-020 — 引入后端：作答提交与甲方审阅台

状态：Accepted（公共链接阶段）
日期：2026-10-09
关联：ADR-002（V0.1 没有后端）、ADR-014（报告载荷白名单）、ADR-019（A 层呈现政策）

## 背景

甲方要求两件事：

1. 一个**公共链接**，把测评发给候选人；
2. 一个**后端控制台**，收到每位作答者的材料，用于"确认是否是想要的人"。

这与 ADR-002（V0.1 明确没有后端）直接冲突，并且触碰一条产品硬边界：`RESULT_BOUNDARY_NOTICE`
写着"系统不输出单一总分，也不输出录用或淘汰建议，最终判断由人结合原始回答作出"，A 层政策
进一步规定 `useForAdmissionDecision: false`。

所以这一轮要同时做两件看起来矛盾的事：**加后端**，并且**不让后端变成一个自动判决器**。

## 决策

### 1. 后端只做三件事，不做第四件

**做**：接收提交（校验邀请码 + 幂等写入）、派生审阅摘要、提供审阅台读取与记录人工结论。

**不做**：输出"是否适合"。

审阅摘要的类型里**不存在** `recommendation` / `verdict` / `pass` / `rank` 这类字段，
而且 `tests/unit/submission-contract.test.ts` 用两条机制把它钉住：遍历摘要的**顶层键**白名单，
以及断言每个角色的适配结果只有 `roleId/name/fitScore/coverage/contributingDimensions`。

> 为什么用键白名单而不是在序列化 JSON 里搜关键词：第一版就是搜关键词，结果它匹配到了测试自己
> 用的种子 `no-verdict`——而一个命名良好的 `recommendation` 字段反而可能被漏掉。检查结构比
> 检查字符串更接近要保护的东西。

审阅台的四个结论标签都写成**审阅人自己的动作**（待定 / 想进一步了解 / 材料不足需要补充 /
本轮不合适），并且**理由必填**：一个只有状态没有理由的记录，几周后连审阅人自己都看不懂当时
为什么这么判。这不是产品的判决，是工作记录。

### 2. 提交是**显式动作**，不是自动上报

作答者点"提交给发起方"之前会看到逐条列出"这次会上传什么"，并且必须自己填联系方式。
默认状态下（未配置审阅台地址）提交面板显示"不会上传任何内容"，而不是一个点不动的按钮。

不自动上报的理由：作答者上传的是自己关于政治—理论议题的自报立场。**同意必须是可拒绝的**，
而不是"不同意就别用"。技术上它也不自动：没有邀请码就写不进任何东西。

### 3. 邀请码是唯一的写入闸门

`POST /api/submit` 要求一个有效的邀请码，码存在 D1 里，可以限次数、设过期、随时停用。
限流（内存固定窗口）只是把明显的突发挡掉——Workers 的隔离实例随时回收，内存计数既不跨实例
也不持久，所以它不是防线；**码才是**。

### 4. 审阅台口令用 secret，且常量时间比较

`ADMIN_TOKEN` 通过 `wrangler secret put` 设置，不进仓库、不进 wrangler.toml。比较用逐字节
XOR 累加而不是 `===`：`===` 在第一个不同的字节处返回，理论上可被逐字节爆破，而对一台公网可达
的 Worker 来说这个修正的代价是零。口令短于 24 字符直接判定为配置错误并拒绝——一个 4 字符的
口令等于没有口令，而这件事不会有人发现，除非我们主动说出来。

### 5. 跨域用精确白名单，不用 `*`

作答端在 Pages，Worker 在另一个域名，所以需要 CORS。配 `*` 意味着任何网站都能代表你的作答者
向这台 Worker 提交数据。白名单是精确匹配（区分 scheme/host/port）：`https://app.example.com.evil.test`
进不来。忘了配 `ALLOWED_ORIGINS` 会让所有跨域提交静默失败，所以 `/api/health` 与部署检查都会
把这条报出来。

### 6. 载荷沿用 ADR-014 的白名单，并**撤掉**一句已经不准的话

提交物由 `buildReportPayload` 的同一套白名单思路构造：不含 API Key、不含浏览器信息、不含历史记录。
`ReviewSummary` 里额外带上了 A 层六部分的**原始材料**——这正是甲方要看的东西——但它被放在独立
字段里、不带任何汇总数字。

同时把 prompt v1 的第 5 条约束（"不把理论层解释为政治立场"）撤掉：A2/A3 现在**确实**承载答题者
自报的议题立场，继续沿用会造成两种相反的错误。详见 ADR-019。

### 7. 存派生数据必须带版本列

审阅摘要派生自正文，但为了列表页不读正文而被存下来。摘要形状一演进，旧行就缺字段：第一次撞上
时详情页整个白屏（`reading 'map'`），而列表页正常，看起来像界面 bug。

修法是把形状版本存成**独立列**（不是 JSON 信封），读时版本落后就**用正文重建并回写**。
为什么不把信封塞进 JSON：列表查询**不读 payload**（不读它正是存摘要的全部理由），所以它需要
一个便宜的判据；信封在 JSON 里意味着列表页只能得出"这行旧了，我修不了"，表现为一行空白——
而空白行会被读成"这个人什么都没交"，恰好是错的。

## 后果

- 新增一份独立产物：审阅台（`admin/` → `worker/assets/`），与作答端分开构建。作答端要发给陌生人、
  必须轻、必须能离线；审阅台只给甲方、依赖网络。编在一起会让作答端平白多背一份没人用的代码。
- D1 免费版有每日行读上限（自 2026-09-01 起超限直接报错）。因此所有列表查询都带索引与 LIMIT，
  分页在 SQL 层做而不是在 JS 层切片——后者会让行读成本与库大小成正比，而不是与页大小成正比。
- 隐私说明、提交前须知、导出审计都同步更新。导出 JSON 会剥掉邀请码。
- 撤回是**软删**（`withdrawn = 1`）：审阅台不再展示，但"收到过又撤回了"这件事留下痕迹。
- 部署需要甲方自己的 Cloudflare 账号。这一步需要人参与，见 `docs/deployment/public-link.md`。
