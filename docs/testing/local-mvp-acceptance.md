# Local MVP 验收记录

构建：`npm run build` 产物 + `npx vite preview --port 4173`
地址：<http://localhost:4173>
日期：2026-10-07

本文件记录 **Local MVP brief §26 那 20 步手动验收** 的实际状态。它严格区分三件事：

- **机器验证**：Playwright 在真实 Chromium 中通过真实 UI 驱动，可重复执行（`npm run e2e`）。
- **人工待确认**：需要一个人在浏览器里点一遍并给出主观判断的步骤。
- **未验证**：没有任何证据的步骤。

自动化测试是通过真实界面驱动的，但**它不是人**。所以下面凡是没有标注「人工待确认」的，都是机器证据；我一个人在命令行里跑不出「人觉得这个流程顺不顺」这个结论。

## 人工待确认（我无法替代你判断的部分）

1. **流程手感**：抽题、逐题作答、跳题、返回，在你自己的使用节奏下是否顺手。
2. **打印 / 另存为 PDF 的实际版式**：分页位置、字体、是否有截断。机器只能证明「打印媒体下隐藏了什么、保留了什么」。
3. **真实第三方端点的直连**：选一个你自己的服务商，填真实 Key，点「测试连接」看是否返回「连接正常」。我没用任何真实 Key 跑过这一步。
4. **真实 AI 报告质量**：用真实模型生成一次报告，看它是否守住了八个小节与边界要求。
5. **断网开关的一次人工体验**：把浏览器 DevTools 设为 Offline，手动点一遍核心流程，确认没有白屏。

## 运行方式

```bash
npm run build
npm run preview            # http://localhost:4173
```

或者在本机做一次完整回归：

```bash
npm run gate:local         # lint + format + typecheck + 两个校验器 + 覆盖率 + 本地 E2E（桌面）
npm run e2e                # 桌面 + 移动两个 viewport 的全部 44 个 E2E
npm run gate:local:fast    # 跳过 E2E 的快速回归
```
