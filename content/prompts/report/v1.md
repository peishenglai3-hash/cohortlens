# 报告 Prompt v1 — 人类可读镜像

版本标识：`report-prompt-v1`
实现：`src/infrastructure/ai/prompts/report-prompt.ts`（**代码侧为唯一执行版本**）
用途：给人类审阅与修改用。改这个文件不会自动改变运行行为；要改行为请同步改 TS 常量。

> 为什么用 TS 常量而不是构建时读取这个 md：报告 Prompt 必须能在无网络、无 fetch、无插件配置的情况下工作（Local First）。用构建时读取会引入一个新的失败点，而收益只是"不用改代码"。这里选择把执行版本放在代码里，把这份 md 作为可读镜像，并在两边各自标注版本号。

## 输出结构（必须严格遵守，顺序固定）

1. `## 整体概况`
2. `## 主要优势`
3. `## 合作方式`
4. `## 任务风格`
5. `## 适合承担的工作类型`
6. `## 可能的磨合点`
7. `## 建议进一步人工了解的问题`
8. `## 测评局限性`

## 硬性约束（违反任何一条即为不合格输出）

1. 不重新打分。所有分数都已由本地引擎算好，只能引用，不能修改、加权、相加或重新归一化。
2. 不产生任何总分、综合分、排名、等级或百分位。
3. 不判断这个人是"谁"。只描述"当前这份问卷的回答呈现出什么"。
4. 不输出：录用、淘汰、通过、不通过、政治可靠、政治不可靠、忠诚、意识形态纯度、值得信任、不值得信任、危险人物、撒谎概率、欺骗指数、真实性评分。
5. 不把理论层（`theory_value`）结果解释为政治立场、政治倾向或任何政治属性。理论层只描述概念理解、理论与现实的连接、组织判断与反身性判断。
6. 不做心理诊断，不推测精神健康状况，不推测家庭、健康、性取向、宗教、民族等未提供的信息。
7. 不用单个答案下强结论。当某个维度只有 1-2 道题支撑或置信度偏低时，必须明确说明该维度材料不足。
8. 不推测结构化结果里没有的信息。缺什么就说缺什么。
9. 引用证据时只使用给出的 question id，不编造题目内容，不编造答题者选了什么。

## 输入载荷

由 `buildReportPayload` 白名单构造（ADR-014）。进入载荷的字段：

- `promptVersion`、`versions`（题库 / 评分 / 角色模型 / 题库语言）
- `dimensions[]`：`id`、`label`、`layer`、`score`、`band`、`items`、`confidence`、`evidenceQuestionIds`
- `roleFits[]`：`roleId`、`name`、`fitScore`、`coverage`
- `strengths[]`、`developmentAreas[]`、`consistency`、`limitations[]`、`boundaries[]`

**不进入载荷**：作答原文、所选选项 id、session id、result id、任何身份字段、任何 API Key。

## 输出后的处理

模型返回的文本在显示与落盘之前先过 `maskForbiddenLanguage`。命中禁用词即替换为 `[已按产品边界屏蔽]`，并把命中词记入 `ReportRecord.sanitizedViolations`，在报告顶部告知用户。

渲染使用自写的小型 Markdown 渲染器（标题 / 列表 / 引用 / 段落），全流程无 `dangerouslySetInnerHTML`。
